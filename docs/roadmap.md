# Roadmap and current limits

The 0.1.0 goal is one complete Windows workflow: select a project/task, observe approved capabilities, preview context, launch one independent Codex terminal and query current CLA evidence. The following are future work, not delivered functionality or promises.

## Possible next work

- Broader Windows and Python-version test matrices, longer operational soak tests and accessibility review.
- Authenticode signing and a reviewed per-user installer after portable distribution is dependable.
- Better non-NVIDIA GPU telemetry and additional bounded provider adapters.
- Optional, separately approved specialist capability checks and real bridge handshake diagnostics.
- Stronger dependency provenance/release automation and explicit source-licensing decision before public distribution.
- Configurable local history retention and more granular approved-evidence scopes.
- WSL launching only after independent launch, permission and filesystem tests.
- Embedded-terminal experiments only after preserving correct interactive Codex behavior and independent lifecycle.

## Deliberate boundaries

CLA is not a shell server, system optimizer, replacement Codex installation, universal specialist bridge, model benchmark or calibration tool. Qwen calibration is not part of the roadmap. It does not automatically stop resource consumers, tune GPU layers, import heavy frameworks at startup, launch stopped WSL distributions or install executable plugins found in projects.

Windows x64 is the tested desktop target. A Python source tree and wheel declaration do not establish Linux/macOS GUI support. The first release is private, experimental and unsigned; it does not claim production readiness, independent security certification or bit-for-bit reproducible binaries.
